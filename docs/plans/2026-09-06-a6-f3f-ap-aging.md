# A6-F3F — AP Aging & Vendor Financial Projection

## Goal

Project Accounts Payable reporting from canonical Vendor Bill, payment allocation, payment schedule and Finance transaction truth. Do not create an editable AP balance ledger.

## Execution-time evidence

- The package branch was re-aligned with execution-time `main`; current-main compatibility must be rechecked again before owner merge because parallel Modulex work continues.
- Production has canonical `vendor_invoices`, `vendor_invoice_payment_allocations`, `vendor_payment_schedules`, `finance_transactions`, `finance_payment_instruments`, `finance_transaction_links`.
- Production F3F migration/RPCs remain intentionally absent before merge; the audited production AP data set currently has 0 Vendor Bills, 0 allocations, 0 payment schedules and 0 Vendor Payment transactions/instruments.
- F3B already derives bill `paid_amount`, `outstanding_amount`, payment state and stores bill `base_amount` / FX snapshot.
- F3C already projects Vendor Payments and check lifecycle (`issued`, `cleared`, `voided`, `returned`).
- F3D already projects planned Vendor Payment Schedules separately from actual settlement.
- Existing authenticated Finance read wrappers use a public `SECURITY DEFINER`, pinned-empty-`search_path` bridge into revoked private Finance cores. F3F follows the same boundary instead of exposing private functions.
- Existing Vendor detail is canonical identity/contact/compliance data and does not own financial balances.

## Locked ownership

- Vendor Bill/payable: AP truth.
- Bill payment allocation: settlement truth.
- Vendor Payment: Finance money-movement truth.
- Payment Schedule: planned operational date/amount only.
- Check lifecycle: Finance payment instrument truth.
- F3F: projection only; no editable totals.

## Aging contract

- Include only `vendor_invoices.status = 'open'` with derived outstanding amount greater than zero.
- `due_date is null` or `due_date >= as_of` → `current`.
- 1–30 days past due → `1_30`.
- 31–60 days past due → `31_60`.
- 61–90 days past due → `61_90`.
- More than 90 days past due → `90_plus`.
- Draft, void and fully paid bills do not enter the projection.
- Scheduled payments never reduce canonical paid/outstanding settlement truth; they are presented only as planning context.
- Historical main-currency projection uses stored bill/transaction base snapshots. F3F does not silently revalue old AP with today's FX.

## Acceptance

- Open AP, overdue, due-soon and aging buckets derive from open Vendor Bills and canonical allocation helpers.
- Vendor-filtered payment/check and schedule history reuse existing F3C/F3D RPCs.
- Main-currency totals use stored historical base snapshots; unresolved historical conversion is visible.
- Private projection cores require `finance.view`, use `SECURITY DEFINER` with `search_path=''`, and are revoked from app roles.
- Public wrappers are authenticated-only `SECURITY DEFINER` bridges with pinned empty `search_path`; anon/public execute remains revoked.
- `/finance/ap-aging` is discoverable in the Finance sidebar under `finance.view` and from Finance Overview.
- No new AP balance table, payment engine, schedule engine, check engine or permission vocabulary.
- Admin UI uses shared primitives and must pass strict UI, route regression, RBAC, typecheck, lint and production build.
- Store migration CI must verify the byte-identical migration mirror.
