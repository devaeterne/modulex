# A6-F3F — AP Aging & Vendor Financial Projection

## Goal

Project Accounts Payable reporting from canonical Vendor Bill, payment allocation, payment schedule and Finance transaction truth. Do not create an editable AP balance ledger.

## Execution-time evidence

- Current base: `main` at F3E merge `04d0d3e5230ca6d722c2460efe041de72a8f1050`.
- Production has canonical `vendor_invoices`, `vendor_invoice_payment_allocations`, `vendor_payment_schedules`, `finance_transactions`, `finance_payment_instruments`, `finance_transaction_links`.
- F3B already derives bill `paid_amount`, `outstanding_amount`, payment state and stores bill `base_amount` / FX snapshot.
- F3C already projects Vendor Payments and check lifecycle (`issued`, `cleared`, `voided`, `returned`).
- F3D already projects planned/overdue/settled Vendor Payment Schedules.
- No AP Aging RPC or AP Aging Admin page existed at package start.
- Existing Vendor detail is canonical identity/contact/compliance data and does not own financial balances.

## Delta matrix

| Requirement | Existing asset | Decision | F3F delta | Compatibility |
| --- | --- | --- | --- | --- |
| Bill outstanding | F3B `vendor_invoices` + `vendor_invoice_paid_amount` | REUSE | Project it into aging buckets | No bill mutation |
| Main-currency AP | Stored bill `base_amount` + `finance_base_currency()` | REUSE / EXTEND | Pro-rate stored historical bill snapshot across remaining outstanding | Missing cross-currency snapshots surface as `unconverted`, never silent zero |
| Payment history | F3C `get_vendor_payments_page` | REUSE | Vendor-filtered drill-down | Finance transaction truth unchanged |
| Check lifecycle | F3C `finance_payment_instruments` | REUSE | Summary for issued/cleared/returned checks | No second check state |
| Scheduled payments | F3D `vendor_payment_schedules` | REUSE | Scheduled AP summary and Vendor drill-down | Schedule remains non-ledger operational plan |
| AP aging buckets | No canonical read model | NEW — read projection only | `current`, `1_30`, `31_60`, `61_90`, `90_plus` | No table/source-of-truth created |
| Vendor financial summary | Vendor master + existing AP/payment/schedule projections | EXTEND | Vendor filter on AP Aging page | Vendor master remains identity/compliance owner |
| AP Aging UI | No existing AP report surface | NEW — read-only UI | `/finance/ap-aging` linked from Finance Overview | No new permission vocabulary or duplicate Reports hub |

## Locked ownership

- Vendor Bill/payable: AP truth.
- Bill payment allocation: settlement truth.
- Vendor Payment: Finance money-movement truth.
- Payment Schedule: planned operational date/amount only.
- Check lifecycle: Finance payment instrument truth.
- F3F: projection only; no editable totals.

## Acceptance

- Open AP, overdue, due-soon and aging buckets derive from open Vendor Bills and append-only allocations.
- Vendor-filtered payment/check and schedule history reuse existing F3C/F3D RPCs.
- Main-currency totals use stored historical base snapshots; unresolved historical conversion is visible.
- Private projection cores require `finance.view`; public wrappers remain authenticated-only.
- No new AP balance table, payment engine, schedule engine, check engine or permission vocabulary.
- Admin UI uses shared primitives and passes strict UI, typecheck, lint and production build.

## Rollout

Source and migration are prepared on `feat/a6-f3f-ap-aging`. Production migration is not applied before merge. After merge, apply `a6_finance_ap_aging`, verify RPC ACLs/results, then close F3F and advance to A6-F4.
